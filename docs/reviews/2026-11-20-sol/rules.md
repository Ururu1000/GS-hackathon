# Normalization and rule engine review

## Verdict

The raw-plus-canonical envelope supports all four Appendix A examples with explicit mapping, grouping and routing semantics. Unknown JSON can be onboarded without a deploy or an LLM.
The design needs a shared configuration revision, conservative candidate selection, and replay semantics before it can substantiate the laptop throughput target.

## Scalability — findings

- **High — §2/§5, local atomicity only.** ArcSwap is appropriate for read-mostly state. One immutable snapshot should contain detectors, typed mappings, rule programs, indexes and templates. Load it once per event. Use a versioned Postgres snapshot as authority, validated via one API/import path with compare-and-swap revision checks. Run one debounced directory importer and rescan on rename. Replicas load on startup/reconnect and reconcile periodically, with LISTEN/NOTIFY as a hint. Retain the previous valid snapshot on failure and surface replica revision lag. Replicas converge asynchronously. [ArcSwap 1.8.0](https://docs.rs/arc-swap/1.8.0/arc_swap/), [notify 8.2.0](https://docs.rs/notify/8.2.0/notify/).
- **High — §2, indexing can silently miss matches.** A conjunction can use a necessary equality on schema, fields.type or envelope source. An OR is indexable only if each arm has a safe selector, using their union. Start by indexing only necessary equalities in top-level conjunctions and put all other trees and raw CEL in a fallback bucket. Union and deduplicate candidate IDs, then run the full predicate. Scan cost still grows with fallback count and hot bucket size. Verify indexed results against an exhaustive scan.
- **High — §5, replay after partial fanout.** Preserve event ID across broker redelivery and commit each partition's contiguous input offset only after all match publishes are acknowledged. Stamp stable match ID (event ID, rule ID) and a separate config revision. Prefer Kafka transactions for matcher outputs plus raw offsets if the initial broker spike passes. Aggregation needs durable idempotency across the supported replay horizon, including across changed partition keys, when using separate commits or collapsing source redelivery. Transactional consumers use read_committed. Replay across a configuration update can change the set of emitted rules. Exact replay would require binding inputs to retained revisions. Use a new rule ID for changed grouping identity in the MVP.
- **High — §2/§5, CPU and fanout dominate at scale.** Partitioned consumers let matcher workers scale horizontally up to the raw partition count. Parse JSON once, lazily build one reusable CEL context per event, and bound queues/in-flight bytes so bursts create visible broker lag. Defer presentation rendering and avoid duplicating full raw payloads per match where consumers can use a context projection and retained event reference. Render a playground preview only on request. At 20k events/s, four fully occupied CPU cores give a theoretical 200 µs of total CPU per event before broker, DB, browser and runtime overhead. Measure on the actual laptop with 10/100/1,000 rules, selective and all-fallback rules, common and skewed sources, varied payloads/match fanout, and cold boot/reload/bursts. Record candidate counts, match rate, CPU, lag, and ingest-to-browser p50/p99. Report five-minute grouping separately. The target is plausible for a selective workload, with evidence pending.
- **Medium — §2/§4.2, overflow and replica-local samples.** Per-schema rings are unbounded in aggregate when arbitrary shapes create new IDs, and the API replica may hold no sample. Publish bounded sampled references or previews to shared broker-backed discovery with TTL, a global entry/byte budget and per-source sampling. Keep raw events in Kafka. Never put schema hashes or event IDs in metric labels.

## Flexibility — findings

- **High — §4.1–4.2, ambiguous detection and string coercion.** Keep transport source separate from producer/service. Prefer explicit source mapping, then source-scoped discriminators with typed path-equals and exists tests and explicit priorities. A tie becomes unknown with a diagnostic. Path existence alone cannot distinguish events sharing the same shape. Use typed extraction, enum conversion and RFC3339/epoch-ms timestamp conversion. A failed optional conversion leaves the field absent with diagnostics. A resolved flag must be boolean. Use a documented JSON Pointer form for arbitrary keys/array indices and restricted dot syntax for common paths.
- **High — §4.2, unseen-schema demo.** Accept and retain unknown JSON and run raw-path rules immediately. Version a bounded structural signature built from sorted escaped paths with array position normalized, ignoring values. Treat it as discovery grouping because optional keys split and equal shapes collide. Let judges pick or paste the observed sample, dry-run, publish a rule, and explicitly resubmit the sample with a fresh ID. Mapping and LLM proposals can follow independently. Existing transport instances and new schemas are config. A new transport kind needs a Source implementation.
- **High — §4.3/§5, undefined CEL semantics.** Use cel-interpreter 0.10.0 for the MVP operator subset. Program::compile parses and Program::execute evaluates to a dynamic value. Validate operator/arity/typed operands and require Boolean results. Lower paths/literals via safe encoding or bind them as typed variables. Keep missing distinct from JSON null. Define comparisons on absent or incompatible values as false, including neq/not_in, and document how explicit not negates that result. Make exists true for present null. Test numeric boundaries, regex, array/object paths and short-circuiting. Reject malformed regex at publish and precompile it. Report CEL runtime errors against the specific rule and continue processing other rules. Bound payload and expression complexity. Defer handwritten CEL or gate it behind an AST allowlist and the same result policy. [Crate and examples](https://docs.rs/crate/cel-interpreter/0.10.0), [interpreter source](https://docs.rs/cel-interpreter/0.10.0/src/cel_interpreter/lib.rs.html).
- **Medium — §4.3, templates and identity.** MiniJinja fits presentation with compiled templates, strict undefined handling, registered money formatting, output limits, context-aware escaping and a render budget. Explicitly provide canonical/raw context and any legacy aliases such as workflowId. Surface preview errors and use a plain alert fallback on runtime render failure. Derive dedup/group identity from typed path tuples independent of display fields, with an explicit missing-key diagnostic. [MiniJinja 2.24.0 environment](https://docs.rs/minijinja/2.24.0/minijinja/struct.Environment.html).

## Hackathon risk

Time-box the first CEL spike to the Appendix predicates, missing/null/type behavior, regex and concurrent execution. Crate APIs were verified against docs and source. No runtime compatibility or throughput measurement was possible at the design stage. Ship the typed condition tree and simple typed mappings first. Build the manual unknown-schema flow early and defer AI, handwritten CEL, and generalized detector/index extraction until the demo works. Use one compiler for publish and draft preview.

## Proposed spec edits

- **§4.1–4.2, replace detection/mapping contract.** “Preserve original JSON and stable ingestion metadata. Select mappings by explicit source pin or highest-priority source-scoped typed detector. Ties and misses enter bounded unknown-schema discovery. Map canonical fields by typed extraction and explicit conversion. Unknown samples can be used to draft, test and publish raw-path rules, then explicitly replayed.”
- **§4.3, replace condition compilation paragraph.** “Compile validated condition trees to CEL and require a Boolean result. Resolve paths with typed values and separate presence metadata. Missing or incompatible operands make comparison leaves false. A present null satisfies exists. Use one compiler for publish and dry-run. Bound input and expression complexity and version the operator contract.”
- **§4.3–4.4, add routing and key contract.** “Dedup and group keys are typed tuples independent of display fields. Missing required key values surface a per-rule diagnostic. Grouped matches use the group tuple for partitioning. Explicit channels take precedence over preferences. Evaluate recipient work hours at first routing in their IANA timezone using a start-inclusive, end-exclusive interval and persist the selected channels for retries.”
- **§2 matcher and §5 steps 1–2, replace hot path contract.** “An event uses one validated snapshot revision covering detectors, mappings, indexed CEL and templates. A single file importer and API publish through the same revision-checked Postgres transaction. Matchers reconcile on startup, reconnect, notify and periodic polling. Candidate selection uses necessary equalities plus a fallback bucket. Publish stable match IDs and revision before committing input offsets. Defer presentation until alert materialization and report replay guarantees across configuration changes.”
