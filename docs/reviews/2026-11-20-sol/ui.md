# UI and API review

## Verdict

Use React/TypeScript for the judged demo unless a three-hour GPUI spike passes the actual editor, accessibility and reconnect flows. GPUI WASM has credible upstream support, but the current spike would mainly prove that a canvas opens.
The thin-client design is sound. The draft needs a recovery protocol and typed payloads before two frontends can independently implement it.

## Scalability — findings

- **High · §2/§8, resume can lose updates.** An alert revision orders one alert. Kafka offsets order one partition. Neither gives the whole team stream a scalar cursor. For M1, every API replica starts its own Kafka consumer group and waits for assignment before serving streams. Subscribe to the replica broadcast before reading the authorized current feed page from PG. Send a `snapshot` event that replaces the page, then drain buffered absolute upserts and removals. Discard older or equal per-alert revisions and restart on overflow, consumer gap or rebalance. Reconnect to any replica and repeat. Commit each visible mutation and its UI outbox record together, including ack/resolve. Persist scope and revision. UI events must survive dispatch cancellation. A delayed update for a row absent from a filtered snapshot can resurrect a stale row. Validate unknown IDs against the current authorized PG projection in batches before inserting, and keep removal revisions for the life of the connection with a bounded cache and resnapshot on overflow. Details refetch on delivery/approval invalidation and reconnect.
- **Medium · true Last-Event-ID is a later feature.** If replay is kept as a requirement, use a durable, scope-bound feed log with a commit-ordered cursor, bounded retention and snapshot watermark from the same consistent read. A bare PG sequence can allocate IDs out of commit order. Resume exclusively after the cursor, replay through a captured watermark while buffering live updates, then drain and switch to live. Reset for invalid/expired cursors or visibility changes. Per-alert revision still makes duplicate outbox delivery harmless. Return no SSE IDs in the snapshot-only MVP.
- **High · §2/§7, fan-out scales with both replicas and listeners.** Every replica decodes the full topic, and the hottest team still costs one write per viewer per update. Use a per-scope in-memory subscriber registry, bounded buffers, serialized payload reuse and coalescing of absolute counter updates by alert ID. Time out slow sockets and force resnapshot. Use heartbeats and disable proxy buffering. Serve a bounded recent page with stable keyset order `(first_seen,id)`, a matching scope/filter index, and independent history pagination. Virtualize rows, batch client updates per frame, and preserve scroll position with a new-alert indicator. Update or remove visible rows when filters change membership and refill the page when needed. Keep full bodies, samples and audit history on demand.
- **High · §2/§9, the latency target needs workload boundaries.** 20k raw events/s on Compose is plausible as a measured low-output workload. At 20k new alerts/s, PG mutations/outbox and SSE/browser fan-out are unproven. A one-second counter flush alone cannot meet 250 ms for most duplicate ticks. Report sustained accepted and processed input rates, alert/update rates, rule match and duplicate ratios, viewers, payload sizes and backlog. Separate ingest-to-first-browser-event, browser render lag, duplicate convergence, group-window delay and simulated gateway acceptance. Run high-cardinality and hot-key cases and force reconnect to a different API replica during writes. Require snapshot/detail to converge to PG and report p50/p99 from correlated events. No performance claim is verified at design stage.

## Flexibility — findings

- **High · §8, endpoint names alone leave frontend-specific assumptions.** Add an OpenAPI schema and SSE fixtures covering the feed projection, detail, mutations, status transitions and error bodies. Include session/scope selection, same-origin cookie auth for EventSource and CSRF protection for writes. Authorize list, stream, detail and mutations consistently. Define timestamps, enum values, filter and cursor semantics, method responses, and expected-version conflicts on edits and transitions. Add APIs or explicitly defer §7 dependencies for team preferences, schema discovery/mapping, fire counts, occurrence series, mock-device events and proposal creation. Keep HTML fragment routes optional for htmx.
- **High · §7/§8, editor needs one authoritative draft.** Use a versioned rule schema shared by YAML, form and API. Support nested condition groups and typed values. A CEL rule opens in an advanced text editor and preserves its expression on round-trip. Parse YAML before replacing the visual draft. Invalid text stays editable with line/column feedback. Test unsaved rules against pasted JSON or an authorized recent sample. Use the same normalization, evaluator and renderer with zero writes or dispatches. Return node-addressed match/no-match/skipped/error diagnostics and template warnings. Debounce and discard stale responses. Seed the editor with the three Appendix A samples and guided defaults. New raw fields and schemas can be tested without a mapping. New operators need backend and editor support unless exposed through the advanced expression editor.
- **Medium · §4.3/§4.5/§7, per-rule presentation needs a durable projection.** The template/field/colour model covers the brief through config. Save rendered title/body, ordered labelled field values, semantic colour token, severity and rule revision with the alert. Validate templates and colour tokens, define missing-field behavior and render untrusted text safely. Use a visible severity label as well as colour. Preview the same alert card used by the feed. Define whether later occurrences refresh the card. Default to the opening rule revision for an existing alert, with live state such as count and status updated separately. Keep dedup identity independent of display fields so a presentation edit cannot split an incident.
- **Medium · extension boundaries.** Source/schema and runbook choices can be config-driven with raw-path testing and explicit runbook format selection, including plain text. New adapter/action/channel implementations still need backend code. Use registry-provided labels and schema metadata if a new registered option should appear in the UI without a frontend release. Render unknown delivery types generically.

## Hackathon risk

- **Checked registry and upstream manifests.** Zed's internal crate name is `gpui_web`. crates.io’s sparse index lists `gpui-pre-web 0.3.13`, a snapshot of Zed at `125ca86`. No `gpui-web` registry entry surfaced. Longbridge publishes `gpui-component 0.10.0`. The tagged GPUI Kit web gallery and deployment workflow establish a supported WASM configuration, and Kit `0.10.0` pins `gpui-pre-web =0.3.12`. Use the matched upstream graph and features for the spike even though a newer backend snapshot exists. Native feature parity, local compilation and browser behavior remain unverified. [Backend on docs.rs](https://docs.rs/crate/gpui-pre-web/0.3.13) · [Backend on crates.io](https://crates.io/crates/gpui-pre-web) · [Component on docs.rs](https://docs.rs/crate/gpui-component/0.10.0) · [Component on crates.io](https://crates.io/crates/gpui-component) · [Kit dependencies](https://github.com/longbridge/gpui-kit/blob/v0.10.0/Cargo.toml) · [WASM gallery workflow](https://github.com/longbridge/gpui-kit/blob/v0.10.0/.github/workflows/release-website.yml)
- **M0 decision after three hours.** Require a clean locked release build that packages static assets separately from native Cargo, opens from Compose on the demo laptop and runs in intended Chromium and Firefox configurations. Test WebGL2 if it is advertised as a fallback. Pass keyboard-only edit/test/save and ack/resolve, visible focus and meaningful accessible names, multiline YAML/JSON paste, selection, clipboard, IME, and runbook links. Demonstrate 5,000 alerts with a proposed 200 aggregate updates/s stress fixture. Require p95 frame time below 33 ms during scrolling, bounded queues, and correct convergence after reconnecting to another replica during the burst. Use the same fixture and contract for the fallback. Missing any gate at the deadline selects React/TS.
- **Fallback order.** React/TS gives native controls, an independently built static client and predictable virtual-list/editor integration. Axum `0.8.9` + htmx is a good shortcut for simpler forms if the team accepts owning a small JS state layer for a virtualized feed and uses Axum fragment routes. Leptos `0.8.23` gives DOM controls and Rust but adds WASM delivery/toolchain work. Pick it only if the team already ships it. Prefer the rule editor, preview, alert detail and live feed over a full device dashboard or visual analytics. [Axum registry](https://crates.io/crates/axum) · [Leptos registry](https://crates.io/crates/leptos)

## Proposed spec edits

- **§2, replace Live feed across API replicas.** Each API replica uses its own consumer group and bounded local broadcast. Commit visible changes, scope, revision and outbox event atomically. On connection, subscribe before reading the authorized PG snapshot. Replace the feed, then apply buffered absolute changes by alert ID and revision. Reconnect and resnapshot after overflow or consumer gap. MVP recovery uses snapshots. Add Last-Event-ID when a durable commit-ordered feed log and retention policy ship.
- **§3.1 and M0, replace decision gate.** Timebox GPUI to three hours using a pinned, compatible GPUI Kit/browser stack and separately built static assets. Pass the editor accessibility, target browser, 5,000-row burst and cross-replica recovery checks. Select React/TypeScript at the deadline if any check fails.
- **§7, replace feed and rule-editor interaction details.** Virtualize the bounded recent page, preserve scroll, and page history by cursor. Expose typed AND/OR groups plus an advanced CEL editor. Test unsaved drafts against raw JSON or a recent sample and show condition diagnostics and the production alert card. Replay an event only through an explicit action. Display rendered snapshots with labelled fields and semantic severity/colour.
- **§8, add the contract.** Publish OpenAPI and SSE fixtures. Snapshot and upsert use the same feed DTO with alert ID, scope, revision, status, count, timestamps and rendered presentation. Specify removal, detail invalidation and reconnect behavior. Define scoped session access, paging, errors and mutation revisions. Rule test takes a draft and raw JSON or sample ID and returns normalized context, per-node results and rendered fields without side effects. Map remaining §7 screens to concrete endpoints or mark them deferred.
- **§9, replace UI latency measurement.** Record first-visible browser event and render lag separately from duplicate convergence, intentional group delay and simulated gateway acceptance. Publish input and output rates, fan-out and backlog for each laptop run.
