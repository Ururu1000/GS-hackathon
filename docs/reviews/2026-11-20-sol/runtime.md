# Rust runtime and deployment review

## Verdict

Keep Tokio, axum, Tower and the single native binary with selectable roles. The architecture can scale within its partition and database limits once backpressure, worker ownership and shutdown are explicit.
The laptop target is plausible for a selective or duplicate-heavy workload. Throughput and latency remain unmeasured, and high-cardinality, high-fanout traffic needs a separate result.

## Scalability — findings

- **High · §2/§3, bounded work.** A burst can exhaust memory or stall API/SSE when matcher CPU, producer queues and outbox retries share one process. Set body and in-flight request limits on the ingest router, bound queues and worker concurrency per role, and yield between matcher batches or use a bounded CPU pool if profiling warrants it. Return 202 after broker acknowledgment, 429 with Retry-After for admission saturation and 503 for broker unavailability or an indeterminate publish timeout. Reuse a stable event ID on retry. Give SSE a bounded per-client buffer and reconnect/resync on overflow. Apply finite request deadlines to ordinary HTTP routes while letting SSE streams remain open.
- **High · §2, ownership and restart.** Partition isolation caps aggregator scale at the partition count. A hot fingerprint or recipient concentrates work on one consumer lane, and new-alert writes still converge on Postgres. Use stable groups per processing role, retain a unique full-feed subscription per API replica, and fence aggregator checkpoint writes with an ownership epoch. On SIGTERM stop admission, drain within the container grace period, and checkpoint only completed work while ownership remains valid. Preserve the alert/outbox/checkpoint transaction and assume at-least-once external sends unless the provider honors the same idempotency key. Single broker and PG are correctly documented as demo failure points.
- **High · §9/§11, performance claim.** At 20k events/s with 1 KiB payloads, raw input alone is about 20 MB/s before other broker traffic, rule fanout and storage. A selective workload can amortize overhead. A workload with one unique alert per event implies 20k alert mutations/s plus outbox work before recipient fanout. Run release builds with an open-loop load generator and record hardware, Docker limits, payload size, rule count, selectivity, unique fingerprints, fanout, accepted and processed rates, backlog slope, errors and p50/p99. Measure first visible SSE alert separately from counter refreshes, intentional group delays and mock provider acceptance. Include a steady run and a burst/recovery run. For a browser latency claim, capture browser receipt or paint explicitly.
- **Medium · §3, measurement.** Add readiness per enabled role and instrument accepted/processed/matched/delivered counters, queue occupancy, broker lag, outbox oldest age, DB pool wait, SSE disconnects and per-stage latency. Use separate delivery and UI histograms with bounded labels such as role and channel. Export Prometheus buckets with a boundary at 250 ms, or merge raw HDR histograms before calculating percentiles across replicas. Keep alert/event IDs in sampled logs, and disable per-event info logging in the benchmark. [Prometheus exporter 0.18.3](https://docs.rs/metrics-exporter-prometheus/0.18.3/metrics_exporter_prometheus/) · [HDR histogram 7.6.0](https://docs.rs/hdrhistogram/7.6.0/hdrhistogram/)

## Flexibility — findings

- **High · §§2/3/10, extension contract.** Use Rust traits and a registry linked into the binary for Source, Channel and Action implementations. Config selects an existing kind and supplies validated instance parameters. New source instances, schema mappings, CEL expressions, routing and templates are data. A new protocol, delivery adapter, condition primitive or runbook parser takes code and a rebuild. Advertise reload by config type. Source reload needs a supervised restart with cursor/offset continuity, so startup-only source config is an acceptable first cut. Hot reload rules and schemas from validated snapshots and keep the last good revision.
- **High · §2, WindowStore.** Redis INCR/EXPIRE cannot implement the existing atomic Postgres checkpoint contract by itself. Keep window storage internal to the engine. If an interface is useful for tests, make its contract include the offsets, deadlines and ownership fence and name the transaction boundary. Any later backend needs a recovery protocol with the same guarantees.
- **Medium · §§3/10, external extensions.** An inbound HTTP source and a registered outbound webhook can cover new integrations through configuration. Version the webhook payload and carry the delivery idempotency key. Action invocation stays behind the existing approval and audit state machine. Defer runtime-loaded libraries and WASM plugins. The latter add ABI, capability and resource-limit design, with no dependency on the browser WASM decision.
- **Medium · §10, crate boundaries.** The listed workspace is workable if dependencies run in one direction. Keep transport-neutral types in core, wire adapters in the binary and inject services into the API. Compile the native workspace with stable Rust and build the browser assets separately. Correct API transport from “REST + WS” to “REST + SSE.”

## Hackathon risk

- Use [Tokio 1.54.1](https://docs.rs/tokio/1.54.1/tokio/), [axum 0.8.9](https://docs.rs/axum/0.8.9/axum/) and [Tower 0.5.3](https://docs.rs/tower/0.5.3/tower/) as candidate M0 pins. Keep Cargo.lock and pin the tested toolchain. [rdkafka 0.39.0](https://docs.rs/crate/rdkafka/0.39.0) supports a bundled CMake build and system linking. Prefer one tested bundled build in a pinned Linux builder and cache native compilation. Verify the actual final image with a produce/consume smoke test. Record cold and warm build times. Switching to JetStream also changes partition ownership, offset and recovery semantics, so it is a design change.
- [gpui-pre-web 0.3.12](https://docs.rs/crate/gpui-pre-web/0.3.12) is published. Publication establishes availability; browser compatibility, rendering and build time still need the three-hour spike. Pin the UI toolchain and serve static assets built in CI. Use axum + HTML/htmx if the spike fails. Test text input, the 1,000-row list and SSE on the demo browser.
- Root Compose should pull pinned demo images with built UI assets. For local edits provide an explicit build override. Use dependency health checks, one idempotent migration/topic/seed bootstrap job, and a smoke event that reaches SSE. Keep scale workers in an override and Grafana optional. Measure checkout to first visible alert on a clean machine with uncached pulls, and report warm startup and source build separately. At M1 run a minimal load test so bottlenecks surface before M6.

Each worker has bounded in-flight work, role-specific readiness and a bounded shutdown drain. Consumer roles use stable groups and the aggregator fences checkpoint writes by partition ownership.
